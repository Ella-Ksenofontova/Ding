# ОБОСНОВАНИЕ ВЫБОРА СУБД

## 1. Анализ требований проекта

### 1.1. Характер данных
- **Тип данных:** структурированные
- **Объём данных:** ~200 Мб
- **Частота операций чтения:** Не более 100 операций в секунду
- **Частота операций записи:** Менее одной операции в секунду
- **Транзакционность:** низкая

### 1.2. Требования к производительности
- **Ожидаемая нагрузка:** Не более 200 запросов в секунду
- **Требования к задержкам:** Не более 20 секунд
- **Пиковые нагрузки:** запись/чтение большого медиафайла, особенно видео

### 1.3. Специфические требования
- **Полнотекстовый поиск:** нет
- **Геопространственные данные:** нет
- **Временные ряды:** нет
- **In-memory вычисления:** нет

## 2. Сравнение отечественных СУБД

| Критерий | PostgreSQL / Тантор | Tarantool |
|----------|---------------------|-----------|
| Тип | Реляционная | In-memory + персистентная |
| Транзакционность | ACID | ACID (ограниченно) |
| Масштабирование | Репликация | Шардирование + репликация |
| Язык запросов | SQL | Lua + SQL-совместимость |
| Производительность (чтение) | Средняя | Очень высокая |
| Производительность (запись) | Средняя | Очень высокая |
| Сложность освоения | Низкая | Средняя |
| Экосистема | Богатая | Развивающаяся |
## 3. Обоснование выбора

**Выбранная СУБД:** PostgreSQL/Tantor

**Обоснование:**
Предполагается, что при работе с системой объём данных будет достаточно небольшим, как и частота операций. При этом для меня в приоритете скорость и простота добавления и изменения кода. Исходя из этих услови, я выбираю PostgreSQL либо СУБД, основанную на ней. 

## 4. План миграции данных
У меня уже имеется папка с выгрузками базы данных (пока там только одна версия). Данные экспортированы в формате SQL, поэтому перенести их в новую реляцционную СУБД не составит труда.
